# Spam Detection Model Comparison

This project addresses supervised binary classification of emails as normal or spam.

The work is organized into two parts: **T1**, focused on problem characterization and an initial comparison of algorithms, and **T2**, focused on optimization, evaluation, and the application of interpretability methods to the selected models. This document describes the procedures carried out without interpreting the results.

## Data and Project Organization

The project uses the [Email Spam Classification Dataset](https://www.kaggle.com/datasets/balaka18/email-spam-classification-dataset-csv), available on Kaggle. The local file contains **5,172 emails and 3,002 columns**: an identifier (`Email No.`), 3,000 numerical word-count features, and the target variable `Prediction`.

The task is to predict the class of each email:

- `Prediction = 0`: normal email;
- `Prediction = 1`: spam.

The main files and directories are:

- [T1 notebook](src/spam-detection.ipynb): data loading, exploratory analysis, preparation, initial comparison, and model evaluation.
- [T2 notebook](src/spam-detection-finetuning.ipynb): candidate selection, optimization, final evaluation, plots, and interpretability methods.
- [T1 specification](<specs/T1 - Enunciado.pdf>) and [T2 specification](<specs/T2 - Enunciado.pdf>): official assignment requirements.
- [T1 report](reports/T1_Report.pdf): the existing report for the first stage.
- `src/data/emails.csv`: local copy of the dataset, ignored by Git.
- `src/results/`: text reports, figures, and models generated by the notebooks.

## T1 — Problem Characterization and Spot-Checking

T1 implements the initial data preparation and a comparison of supervised algorithms, following the spot-checking approach described in the assignment.

### 1. Data Loading and Exploratory Analysis

The notebook contains the procedure for downloading the dataset with `kagglehub` and reading the CSV with `pandas`. The exploratory analysis records:

- the number of rows and columns, data types, and number of missing values;
- class distributions in the complete dataset, training set, and test set;
- the 20 features with the highest total word counts;
- the 20 features with the lowest nonzero total word counts.

Summaries are saved as TXT files and figures as PDFs. A full textual preview of the dataset is generated locally, but `dataset_preview.txt` remains ignored by Git.

### 2. Data Preparation and Splitting

The `Email No.` column is removed from the inputs, and `Prediction` is separated as the target variable. The remaining 3,000 columns are used as features.

The split uses `train_test_split`, class stratification, and `random_state=42`:

- **Training:** 4,137 emails, approximately 80% of the data.
- **Test:** 1,035 emails, approximately 20% of the data.

Cross-validation on the training set uses `StratifiedKFold(n_splits=5, shuffle=True, random_state=42)`. All algorithms are evaluated on the same splits.

### 3. TF-IDF Transformation

Since the CSV already contains numerical word counts, preprocessing uses `TfidfTransformer` with the following configuration:

```python
TfidfTransformer(
    norm="l2",
    use_idf=True,
    smooth_idf=True,
    sublinear_tf=True,
)
```

Within each fold, the transformer is fitted only on the internal training data and then applied to validation data. For the final T1 evaluation, TF-IDF is fitted on the full training partition and applied to both training and test data.

### 4. Algorithms and Metrics

Five algorithms were included in the initial comparison:

1. Logistic Regression;
2. Linear SVM;
3. Decision Tree;
4. XGBoost;
5. Neural Network (`MLPClassifier`).

**Accuracy, precision, recall, and F1-score** are calculated for every model and fold. Spam (`1`) is the positive class for the classification metrics. The notebook sorts the initial summary by mean accuracy and records the remaining metrics; the T1 report prioritizes spam precision.

### 5. Spot-Checking and Evaluation

The models are trained and evaluated on the same five folds using default or fixed configurations. This stage does not perform hyperparameter search or classification threshold tuning.

The notebook records the metrics for each fold, calculates the mean and standard deviation for each model, and generates a boxplot of accuracies. It then refits each of the five models on the full training partition and records the four metrics on the test set.

T1 outputs are organized under `src/results/`, including `data_overview/`, `exploratory_analysis/`, `preprocessing/`, `cross_validation/`, and `test_evaluation/`.

## T2 — Optimization, Evaluation, and Interpretability Methods

T2 uses the models selected for the second stage and implements hyperparameter search, finalist evaluation, and the generation of interpretability plots and tables.

### 1. Candidate Selection

The three algorithms selected and documented in the notebook are:

- Neural Network;
- Decision Tree;
- XGBoost.

The notebook's selection section records the context of the choice and the T1 cross-validation metrics used as a reference. The selection was documented before the T2 hyperparameter search.

### 2. Validation Protocol and Pipelines

T2 reproduces the stratified split of approximately 80% training and 20% test data, with `random_state=42`. The search uses only the training partition and the same five stratified splits for the three algorithms. The test partition does not participate in hyperparameter selection.

Each candidate is represented by a `Pipeline` combining `TfidfTransformer` with the estimator. TF-IDF is fitted within each fold's internal training data; the search receives the original word counts.

### 3. Hyperparameter Optimization

The search uses **Optuna**, with `TPESampler` and seed 42. **Twenty trials per algorithm** were run, including the initial reference configuration. Each configuration was evaluated on five folds, for a total of:

- 60 evaluated configurations;
- 300 model fits during cross-validation;
- three final fits of the selected models.

The primary search metric is **mean spam precision**. Accuracy, F1-score, and recall are also recorded.

The search spaces include:

- **Decision Tree:** criterion, depth, minimum split and leaf sizes, feature selection, and pruning.
- **XGBoost:** number of trees, depth, learning rate, sampling, and regularization parameters.
- **Neural Network:** layer structure, activation, regularization, learning rate, and batch size.

Each fold pipeline is saved in `joblib` format, together with text metadata containing parameters, metrics, timings, warnings, and library versions. Study reports and optimization history plots are also saved.

### 4. Final Fitting and Test Evaluation

After the searches are complete, the selected configuration of each algorithm is fitted on the full training partition. The three final pipelines are saved and evaluated on the test set.

For each finalist, the notebook records parameters, predictions, accuracy, precision, recall, F1-score, the selected configuration's cross-validation metrics, and training and prediction times.

The `t2_load_model` function loads a saved pipeline and its parameters. `joblib` files should only be loaded from trusted sources with compatible dependency versions.

### 5. Comparison Visualizations

The notebook loads the saved finalists, reconstructs the test split, and checks the predictions against the saved files. It then generates:

- a confusion matrix for each finalist;
- a comparison chart for accuracy, precision, recall, and F1-score;
- ROC curves and their AUC values;
- precision-recall curves and their average precision values.

### 6. Interpretability Methods

The following procedures reuse the saved final models without rerunning optimization or training:

- **Tree SHAP for Decision Tree and XGBoost:** explains a stratified sample of 400 training emails. It generates mean importance charts, summary plots, and feature tables. The Decision Tree is explained on the spam probability scale; XGBoost is explained on the log-odds scale.
- **Permutation Feature Importance for the Neural Network:** uses the 1,035 emails in the already evaluated test set. Each feature that varies in the set is permuted three times. Changes in precision, recall, F1-score, accuracy, average precision, and log loss are recorded.

Permutation analysis on the test set is descriptive and should not be used to select features, change models, or adjust thresholds in a new iteration using that same set. Neither method establishes causal relationships.

### 7. T2 File Organization

Artifacts are stored directly under `src/results/hyperparameter_optimization/`:

```text
hyperparameter_optimization/
├── figures/                 # Optimization histories
├── text/                    # Search reports and summary
├── models/                  # Pipelines and metadata by model, trial, and fold
├── finalists/               # Final models, predictions, and comparison plots
└── model_interpretation/
    ├── tree_shap/           # Figures and tables for the tree and XGBoost
    └── permutation_importance/  # Figures and table for the neural network
```

Interpretability outputs use fixed directories rather than dated folders. The corresponding cells may overwrite these files when rerun. The optimization function checks for existing experiment artifacts before starting a new search.

## Reproducibility

The notebooks record seeds, splits, preprocessing settings, dependencies, and output paths. The T2 notebook contains dependency installation cells and identifies the cell that starts the full optimization. The interpretability analyses use the saved models and do not require rerunning the hyperparameter search.
